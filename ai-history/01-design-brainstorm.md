The plan is **Stacks**, a reading tracker where progress comes in as events instead of being typed in by hand. Every choice below is aimed at the brief's priority order:

**1. Domain model (scored highest)**
- **Progress is a log, not a field.** Each update is saved as a new `reading_event` row instead of overwriting a number. Current progress, status, pace and estimated finish date are all calculated in SQL from that history.
- **Late updates can't move you backwards.** Current progress uses the update with the latest *reading* time, not the latest *arrival* time, so a delayed sync can't overwrite newer progress. This is the query that would be embarrassing if it were wrong, so it gets a test.
- **Each update is counted once.** A unique key on (source, external ID) means a device resending the same update has no effect.
- **The database blocks cross-user mistakes.** Composite foreign keys make it impossible to put another user's book in your stack, even if the API code had a bug.

**2. API contract**
- Versioned REST under `/v1`, with one error format for everything.
- Requests for another user's data return 404, so nobody can tell whether it exists.
- There are two kinds of key: user keys and device keys. Device keys can only send progress updates and can't read anything.
- The OpenAPI schema generates the TypeScript types the frontend uses.

**3. How the two halves fit**
- **"Sync Kindle" button:** it starts a background job in Postgres, and the UI shows it move from queued to running to done.
- **Simulated Kindle:** the job pulls from a fake Kindle source and writes through the same code path as manual and device updates. A real integration would plug into the same interface.

**4. Tests on the risky parts**
- The progress query: out-of-order and duplicate updates, plus the pace and finish-date maths.
- Access control: cross-user requests, wrong key type, revoked keys, and invalid input.

**5. NOTES.md**
- Says plainly that Kindle has no API and why Open Library replaces Amazon search.
- Keeps an AI log as we go, plus the transcript, as the interviewers suggested.
